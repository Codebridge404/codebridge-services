1. EXECUTIVE ARCHITECTURE OVERVIEW
--------------------------------------------------------------------------------
Transformed the CodeBridge system from a legacy single-container monolith into an
enterprise multi-tier microservices architecture consisting of:
  • API Gateway (Nginx FastCGI Reverse Proxy & WAF on Port 8080)
  • Auth & Identity Service (PHP 8.2-FPM + MySQL Port 3307 + Redis 6379)
  • Operations & POS Service (PHP 8.2-FPM + MySQL Port 3308 + Redis 6380)
  • Scramble Interactive OpenAPI Documentation Hub (/docs, /docs/auth, /docs/operations)
  • Independent background queue workers (Laravel Horizon) for each microservice.

2. DATABASE ARCHITECTURE EVOLUTION: 1 SHARED DB -> 2 DEDICATED ISOLATED DBS
--------------------------------------------------------------------------------
A major milestone completed today was transitioning from a monolithic 1-shared-DB
setup to a strictly isolated Database-per-Service architecture:

  • Before (1 Shared Monolithic Database):
    - Both authentication logic and retail/POS operations shared a single database
      instance (`codebridge_db`).
    - Tight coupling: direct cross-table SQL queries, shared connection pools, and
      cascading failure risks (if POS queries bogged down the DB, login went down).

  • After (2 Dedicated Isolated Microservice Databases):
    - Database 1: `codebridge_auth` (Port 3307)
      * Dedicated Service: Auth & Identity Service
      * Domain Schema: users, personal_access_tokens, tenants, roles, permissions,
        role_permissions, user_roles, api_keys, outlets, departments, employees,
        customers, suppliers, meetings, meeting_rooms.
      * Isolated Admin GUI: phpMyAdmin on Port 8081.
      * Dedicated Cache: Redis on Port 6379.

    - Database 2: `codebridge_operations` (Port 3308)
      * Dedicated Service: Operations & POS Service
      * Domain Schema: products, categories, brands, product_variants,
        inventory_balances, inventory_movements, sales, sale_lines, shifts,
        cash_drawer_movements, payments, payment_attempts, expenses, incomes,
        bank_accounts, purchases, purchase_orders, tables, kitchen_orders.
      * Isolated Admin GUI: phpMyAdmin on Port 8082.
      * Dedicated Cache: Redis on Port 6380.

  • Decoupling Benefits Achieved:
    - Zero Cross-Database Foreign Keys: Operations never directly writes or locks
      Auth tables, eliminating cascading deadlocks.
    - Inter-Service Auth Verification: Operations validates user tokens and roles
      via FastCGI internal networking / HTTP client (`AuthServiceClient.php`)
      without direct SQL coupling.
    - Independent Scaling & Maintenance: Database migrations, backups, and failovers
      for Auth and Operations are completely autonomous.

3. API GATEWAY & ENTERPRISE SECURITY ENHANCEMENTS
--------------------------------------------------------------------------------
  • Gateway WAF (Web Application Firewall):
    - Configured threat inspection blocking malicious scanners, directory traversal,
      hidden file attacks (.env, .git), and GraphQL abuse attempts.
    - Set up IP connection rate-limiting (auth: 10r/s, api: 60r/s, docs: 30r/s).
    - Integrated standard security headers: X-Frame-Options, X-Content-Type-Options,
      Strict-Transport-Security, Content-Security-Policy.
  • Production Cross-Origin Resource Sharing (CORS):
    - Applied uniform CORS configs in auth-service/config/cors.php,
      operations-service/config/cors.php, and gateway/services/docs.conf.
    - Allowed frontend dev/prod origins, headers, credentials, and preflight handling.
  • Interactive Scramble Documentation & Spec:
    - Fixed OpenAPI JSON spec generation and Scramble interactive UI under /docs.
    - Resolved local gateway routing and CORS preflight issues so documentation
      requests run seamlessly from browser without network errors.
